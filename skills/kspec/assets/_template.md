# Specification

State what the project does and which behavior this document defines. Use the project name in the title when known. Keep the sections needed for the product and remove unused headings and placeholder text, including this guidance.

## Shared rules

Describe guarantees and constraints that apply across the product. Keep rules specific to one area in that area's section.

## Area of behavior

Describe inputs, outputs, state changes, and ordering as behavior a reader can check against the running product. Add one section per area, in the order a reader needs them. Use small examples where prose alone is ambiguous.

Record deliberate exclusions or undefined behavior only when they reflect a product decision.

## Errors

Describe rejected inputs or operations, what the product reports, and when the error occurs relative to other output or state changes. Omit this section if errors are covered in the behavior sections.

## Reference

Include a complete grammar, table, or enumeration when the behavior sections need one. Omit this section if there is nothing to collect.
